# Exercise 5 · Build the `webapp` Chart

Work in a scratch directory outside this repo, e.g. `/tmp/webapp`.

## Tasks

1. Create the skeleton:
   ```bash
   mkdir -p /tmp/webapp/templates
   cd /tmp/webapp
   ```

2. Create `Chart.yaml`:
   ```yaml
   apiVersion: v2
   name: webapp
   description: A minimal web app chart for the Helm workshop
   version: 0.1.0
   appVersion: "1.25"
   ```

3. Create `values.yaml`:
   ```yaml
   replicaCount: 1

   image:
     repository: nginx
     tag: "1.25"

   service:
     type: ClusterIP
     port: 80
   ```

4. Create `templates/deployment.yaml`. Use `{{ .Values.<key> }}` to pull in each value instead of hardcoding it:
   ```yaml
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: webapp
   spec:
     replicas: {{ .Values.replicaCount }}
     selector:
       matchLabels:
         app: webapp
     template:
       metadata:
         labels:
           app: webapp
       spec:
         containers:
           - name: webapp
             image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
             ports:
               - containerPort: 80
   ```

5. Create `templates/service.yaml`:
   ```yaml
   apiVersion: v1
   kind: Service
   metadata:
     name: webapp
   spec:
     type: {{ .Values.service.type }}
     selector:
       app: webapp
     ports:
       - port: {{ .Values.service.port }}
         targetPort: 80
   ```

6. Validate before installing — this lints the chart for structural/syntax errors:
   ```bash
   helm lint .
   ```
   Fix anything it flags. It should report `0 chart(s) failed`.

7. Preview the rendered YAML:
   ```bash
   helm template webapp .
   ```
   Check that `{{ .Values.* }}` placeholders were replaced with real values (e.g. `image: "nginx:1.25"`).

8. Install it into your cluster:
   ```bash
   helm install webapp . --namespace helm-basics --create-namespace
   ```

9. Verify:
   ```bash
   kubectl get deployment,pod,svc --namespace helm-basics
   ```
   You should see a `webapp` Deployment with 1/1 pods ready, and a `webapp` Service of type `ClusterIP`.

10. Access it via port-forward:
    ```bash
    kubectl port-forward --namespace helm-basics svc/webapp 8080:80
    ```
    In another terminal: `curl localhost:8080` — you should get the default nginx welcome page HTML. `Ctrl+C` to stop the port-forward.

**Leave this release installed** — Lesson 6 builds directly on it.

## Questions

<details>
<summary>Q1: What would happen if you ran <code>helm install webapp .</code> a second time with the same release name, in the same namespace?</summary>

It would fail with an error that a release named `webapp` already exists in that namespace. To change a running release, you use `helm upgrade`, not another `helm install` — that's Lesson 7.
</details>

<details>
<summary>Q2: Why does <code>templates/deployment.yaml</code> hardcode <code>name: webapp</code> and <code>app: webapp</code> instead of templating those too?</summary>

For a minimal chart it's fine — you'd only ever install one instance in this exercise. In real-world charts, names are usually derived from `{{ .Release.Name }}` (via a helper template) so that multiple releases of the same chart don't collide on resource names. You'll see that pattern in charts generated by `helm create`.
</details>
